一、当前确认路线（V3-01）

Codex 设计 用户已确认：ESP32 终端 ＋ 现有电脑

  • 首版路线：ESP32-S3 方块（已下单微雪 ESP32-S3-LCD-1.47B-M）作为终端，由现有电脑运行连接程序与会话。模块化拆分 ASR / TTS / 会话连接三层，不立即引入多进程网络服务。
  • 同一前台 agent 是采用前提：树莓派常开服务不等于电脑前台同一 agent 持续可用；独立会话不作为替代方案。验证「同一会话接入」是后续采用任何上位机的前提。
  • 树莓派仅后续候选：当前不增加 ARM 实验任务；DS 不安装 ARM 工具链、不开展采购（RES-002 当前审查，责任划分）。

三、音频方案（V3-02）

Codex 设计 首版：按键发起、轮流听说；AEC 待评估

  • 首版形态：按键发起对话、轮流听说（听→说→屏显状态），不预设语音唤醒。
  • 软件 AEC 与独立音频处理器均为待评估候选：乐鑫官方 ESP32-S3 文档已提供接收 mic/ref 的软件 AEC 处理接口 （esp-sr AEC 文档）； 接口存在 ≠ 本项目音频接线与效果已验证。
  • 不作为已批准约束：硬件回采、双麦、XMOS、物理断电开关不得呈现为已定方案；具体接线、器件与验收由 Codex 设计、DS 实现验证。
  • 播放中语音打断：待用户后续决定，当前非已批准开发项。

四、树莓派相关性（后续候选，按 RES-002 当前审查统一，V3-01/V3-03）

结论当前口径（统一后）推荐
借鉴语音卫星状态划分 事件序列（run_start→…→error / announce）可作屏幕状态机裁剪蓝本；结构可借鉴，不含代码许可义务（ESPHome runtime 为 GPLv3，复用代码须固定版本并核实许可，不作一概法律保证） 4/5
树莓派作常开上位机 后续常开语音服务候选；常开服务不等于电脑前台同一 agent 持续可用，同一前台 agent 接入待证明，当前不开展 ARM 实验。Codex CLI 有 Linux arm64 二进制（Apache-2.0），但 app-server 在 arm64 无头行为未查证，须先满足「同一前台 agent」前提 3/5
本地 ASR/TTS Piper 社区自测快于实时、whisper 中文质量与延迟未测；性能未经项目实测，不称已证实足够 3/5
换树莓派做方块主控 当前维持已购 ESP32；缺少同条件测量（ESP32-S3 官方功耗/启动未查证），不作全面优劣判断。Pi 5 16GB $305（2026-10-19 官网读取，非实时价承诺） 1/5
HY 整理 树莓派价值定位为「上位机/服务端候选 + 架构参考」，非首版路线。比较结论均带适用条件与来源；价格标注读取时间、性能不称已证实；架构借鉴不称零成本；不宣称已解决电脑休眠/掉线；换主控不作六项全面劣化结论。
